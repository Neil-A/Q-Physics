# Write in ASD-STE100 Simplified Technical English

Write all prose in ASD-STE100. This includes replies, documents, commit messages, pull request
text and code comments. The reader is a person who is not a specialist. Explain at that level.

## Words

- Use simple, common words. Use a word only with its most basic meaning.
- Use one word for one thing. Do not use a different word for the same thing later.
- Do not use one word for two different things.
- You can use technical names (names of parts, files, tools, tests and data). You can use
  technical verbs (for example "compile", "commit", "merge").
- Do not use phrasal verbs. Write "start", not "kick off". Write "install", not "set up".
- Do not use idioms, slang or figures of speech.
- Do not use contractions. Write "do not", not "don't".
- Do not make a noun cluster of more than three words. Break a long cluster with "of", "for"
  or "in".

## Verbs

- Use only these verb forms: simple present, simple past, future ("will"), the imperative
  (command), and the infinitive.
- You can use the past participle only as an adjective ("the changed file").
- Do not use the past participle with a helping verb to make a complex tense. Write "we
  changed the file", not "we have changed the file".
- Do not use the "-ing" form of a verb, except in a technical name.
- Use the active voice. Say who or what does the action. Use the passive voice only when you
  do not know who did the action, and only in descriptive text.

## Sentences

- Write one idea in one sentence.
- Keep instructions (procedures) to 20 words or fewer per sentence.
- Keep descriptive sentences to 25 words or fewer.
- In an instruction, use the imperative: "Run the test." Give one instruction per sentence,
  unless the two actions occur at the same time.
- Put a condition before the instruction: "If the test fails, read the log."
- Do not omit words to make a sentence shorter. Keep "the", "a", "this" and "that".
- Use connecting words ("then", "but", "because") to show how two sentences relate.

## Paragraphs and structure

- Give each paragraph one topic. Start with the topic sentence.
- Put no more than six sentences in a paragraph.
- Use a vertical list for steps or for a set of items. Number the steps in their sequence.
- Start a warning or a caution with a clear command. Then give the reason.

## Do not change these

These items stay as they are. The rules above do not apply to them:

- code, commands, identifiers, file paths, logs and data values;
- quotations, and the words of a person when you quote them;
- text in an existing document, unless the user tells you to rewrite it.

Project rules in `CLAUDE.md` still apply. If a project rule and this style disagree, obey the
project rule.
